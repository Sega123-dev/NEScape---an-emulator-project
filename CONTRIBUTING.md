# Contributing to NEScape
Thank you for contributing to NEScape!

Whether you're fixing a bug, improving compatibility, optimizing performance or suggesting a new feature, every contribution is appreciated.

# Getting Started

Before contributing, make sure you have:

- A basic understanding of tehnologies written in the README.md
- Git installed.
- CMake installed.
- SDL2 and the required project dependencies.
- A compatible C++ compiler.

Clone the repository:

```bash
git clone https://github.com/Sega123-dev/NEScape---an-emulator-project.git
```

Please refer to the main README for build instructions and additional dependencies.

# How Can You Contribute?

There are several ways to contribute to NEScape.

# Bug Reports

If you encounter a bug, please open an issue and include:

- A clear description of the problem.
- Steps to reproduce it.
- Expected and actual behavior.
- Relevant logs or screenshots.
- The ROM name and mapper, if applicable.

# Feature Suggestions

Have an idea that could improve NEScape? Feel free to open an issue describing your suggestion, why it would be useful and how you envision it working.

# Code Contributions

Code contributions are welcome, including:

- CPU and PPU accuracy improvements.
- Mapper implementations and compatibility fixes.
- Performance optimizations.
- Audio improvements.
- UI and usability enhancements.
- Bug fixes and code refactoring.

# Pull Request Guidelines

Before submitting a pull request:

1. Make sure your changes are relevant to the project.
2. Test your changes before submitting.
3. Keep your code clean and readable.
4. Provide a clear description of what you changed.
5. Reference any related issues.

Please avoid submitting unrelated changes in a single pull request.

# Coding Guidelines

To maintain consistency throughout the project:

- Follow the existing coding arcitecture.
- Use meaningful variable and function names(preferably use CamelCase or snake_case).
- Avoid unnecessary code duplication.
- Comment complex logic where necessary.
- Prioritize correctness and maintainability over unnecessary complexity.

For emulator-related changes, please pay particular attention to timing accuracy, memory mapping and hardware behavior.

# Testing

Changes affecting emulation accuracy should be tested whenever possible.

Please verify that existing functionality remains intact and that your changes do not introduce regressions.

When working with mapper implementations, include the mapper number and relevant test ROMs in your pull request description.

## Questions and Discussions

If you have questions, ideas or concerns, feel free to open an issue or start a discussion.

We appreciate every contribution, regardless of its size.
